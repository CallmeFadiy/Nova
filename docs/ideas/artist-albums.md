# Альбомы по исполнителю

Статус: **реализовано** в `src/store/library.ts` (вариант 1 с канонизацией имён и отдельными совместными проектами). Схема БД не менялась: группировка вычисляется на лету.

## Задача

Сейчас альбомы группируются по паре `album_artist + album` из тегов. Из-за этого один исполнитель может распасться на несколько альбомов:

- `АсперХ` — альбом `AsperX`;
- `АсперХ (Тапок.нет)` — альбом `Topde.net`;
- `AsperX` — альбом `AsperX`.

Нужно, чтобы все три попали в один альбом исполнителя. Но фит не должен растворяться в сольном альбоме:

- `АсперХ, Ctrl+Freak` — отдельный альбом/проект.

При этом нельзя терять настоящие названия альбомов и обложки: они всё ещё полезны.

## Главные трудности

1. **Канонизация имени.** Регистр, кириллица/латиница, лишние пробелы, дефисы, скобки-суффиксы `(Тапок.нет)`, `(Sefon.Pro)`, `[Topde.net]`.
2. **Фит — это не всегда `feat.`** Встречаются `ft.`, `&`, `×`, `x`, `vs`, `при участии`, `совместно`, запятая между именами.
3. **`x` внутри имени.** `AsperX` — это один артист, а `asper x квадрат` — фит. Нужны границы слов и список исключений, а не поиск буквы `x`.
4. **Разные написания одного имени.** `АсперХ` и `AsperX` могут быть одним артистом, а могут — разными. Автоматика ошибается; нужна ручная правка.
5. **Настоящие альбомы.** Если всё свести к «альбом = исполнитель», пропадёт деление на `The First Berserker: Khazan OST` и синглы.

## Варианты реализации

### Вариант 1. Плоский альбом исполнителя (как в запросе)

- У каждого трека вычисляется `artist_key`.
- Если в исполнителе есть признак фита — `album_key = collab:<полная строка исполнителей>`.
- Иначе `album_key = artist:<канонический исполнитель>`.
- В «Альбомах» показывается по одному альбому на исполнителя; настоящий альбом — подпись под названием трека.
- Плюсы: ровно то поведение, которое описано; просто и предсказуемо.
- Минусы: у плодовитого исполнителя один длинный альбом; настоящие альбомы не видны как отдельные сущности.

### Вариант 2. Два уровня: исполнитель → настоящие альбомы + «Все треки»

- Первый уровень — канонический исполнитель.
- Внутри — настоящие альбомы из тегов (`AsperX`, `Topde.net`, `Single`) и виртуальный альбом «Все треки».
- Фит попадает в отдельного исполнителя `АсперХ × Ctrl+Freak`, а не в сольного `АсперХ`.
- Плюсы: сохраняет обложки, годы и структуру; лечит только разнобой в имени; хорошо масштабируется.
- Минусы: это не «один альбом на исполнителя», а дерево; больше экранов.

### Вариант 3. Движок правил и алиасов

- В настройках таблица: каноническое имя, алиасы/регулярки, флаг «считать фитом», флаг «не объединять».
- Автоподсказки: сравнение без регистра, транслитерация, удаление скобочных суффиксов, расстояние Левенштейна.
- Перед применением — предпросмотр: «было 3 альбома → стало 1», список затронутых треков.
- Плюсы: точный контроль для странных имён; можно исправить любую ошибку.
- Минусы: нужен интерфейс и участие пользователя; автоподсказки могут ошибаться.

### Вариант 4. Фолбэк по папкам

- Если тега исполнителя нет, брать имя папки или `Artist - Title` из файла.
- Если несколько папок дают одного исполнителя — объединять, но хранить папку как источник.
- Плюсы: работает для грязных локальных библиотек.
- Минусы: папки часто названы произвольно; не решает фиты.

### Вариант 5. MusicBrainz / AcoustID

- Определять канонического исполнителя и настоящий альбом по аудиоотпечатку или тегам.
- Плюсы: самые точные данные.
- Минусы: сеть, скорость, приватность, зависимость от внешнего сервиса. Для локального плеера — избыточно.

## Рекомендация

**Гибрид 1 + 3**, с возможностью включить 2:

1. По умолчанию — плоский альбом исполнителя, как просил пользователь.
2. Фит определяется по маркерам и правилам; `AsperX` не считается фитом, `asper x квадрат` считается.
3. В настройках — «Исполнители»: алиасы, объединить/разделить, «это не фит», предпросмотр.
4. Настоящий альбом хранится как подпись и как необязательный второй уровень (переключатель «Показывать настоящие альбомы»).

### Пайплайн канонизации

1. Unicode NFKC, trim, схлопнуть пробелы, унифицировать кавычки/дефисы.
2. Удалить хвостовые скобочные суффиксы источников: `(Тапок.нет)`, `(Sefon.Pro)`, `(Topde.net)`, `[mp3]`. Список настраиваемый; `(feat. …)` не удалять.
3. Определить фит по маркерам: `feat`, `ft`, `&`, `×`, ` x ` (с пробелами), `vs`, `при участии`, `совместно`, запятая между именами.
4. Построить ключ: `artist:<casefold>` или `collab:<casefold полной строки>`.
5. Отображаемое имя: самый частый «чистый» вариант, либо ручной алиас.
6. Сохранить в БД: `artist_key`, `artist_display`, `is_collaboration`, `collab_key`, `group_source`.
7. При изменении алиасов пересчитать группировку без изменения файлов.

### Пример

| Тег исполнителя | Ключ | Альбом |
|---|---|---|
| `АсперХ` | `artist:asperx` | АсперХ |
| `АсперХ (Тапок.нет)` | `artist:asperx` | АсперХ |
| `AsperX` | `artist:asperx` | АсперХ |
| `АсперХ, Ctrl+Freak` | `collab:asperx ctrl+freak` | АсперХ × Ctrl+Freak |
| `asper x квадрат` | `collab:asper x kvadrat` | asper x квадрат |

### Что нужно решить

1. Настоящие альбомы: убрать совсем или оставить вторым уровнем?
2. Какое имя показывать для `АсперХ` / `AsperX` — кириллицу, латиницу или самый частый вариант?
3. Фит `АсперХ, Ctrl+Freak` — отдельный альбом только у `АсперХ` или отдельная страница «АсперХ × Ctrl+Freak»?
4. Считать ли `&` и `×` фитом всегда, или только если рядом есть пробелы/известные имена?
5. Нужен ли предпросмотр группировки перед применением?
6. Хотите ли автоматические подсказки алиасов или только ручные правила?

## Что реализовано

- Один плоский альбом на канонического исполнителя.
- Приведение регистра, `_`, дефисов и хвостовых суффиксов источников.
- Транслитерация кириллицы для ключа (`АсперХ` → `asperx`, `Asper X` → `asperx`).
- Отдельный ключ для фитов и совместных проектов (`feat`, `ft`, `&`, `×`, `x` с пробелами, запятая, `при участии`, `совместно`, `vs`).
- Названия настоящих альбомов остаются подписью на карточке и колонкой в списке треков.
- Файлы и теги не изменяются.
